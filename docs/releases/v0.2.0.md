# Agent X Ecosystem v0.2.0

This release brings a simpler first comparison, clearer Chat and Knowledge
flows, and a smaller private-LAN runtime. Core, Benchmark, and RAG are version
0.2.0. The release image manifest records the exact source commit and three
image digests; publishing these images does not upgrade an existing installation.

## Try it

Start from the [README](../../README.md), then follow the [demo guide](../DEMO.md).
Git and Docker are required. Ollama and all model choices are explicit; startup
does not download a model. The default demo profile includes Chat, Knowledge,
and model comparison. Operational workspaces remain in the full profile.

## Quick comparison

Choose two prepared local models and an installed judge, then select **Quick
comparison**. It applies one Basic prompt per category, a 512-token response
limit, one repeat, and one judge. It matches the models' current qualified
performance measurements, resets old advanced settings, and shows a preview
before launch. Missing profiles and incompatible measured contexts have specific
recovery messages. Changed selections cancel outstanding checks.

The normal launch checks still apply. Quick comparison does not create a new
context recommendation or weaken the Full-profile requirement for automatic
recommendations. A judge that is also a contender is identified in the preview;
use an independent judge and representative repeated tasks for quality claims.

Custom test depth is behind a disclosure, with readable, horizontally scrollable
columns on compact screens. The comparison header updates on start and finish,
counts completed runs correctly, and preserves unavailable status/history.

## Other improvements since v0.1.1

- Chat has a clearer interface with expert controls behind **Take the controls**.
  Manual model selection immediately updates its badge. Stop retains partial
  replies; retries and missing-model recovery avoid duplicate user messages.
  Already-dispatched runtime work may finish after visible streaming stops.
- Knowledge offers clearer upload validation, recoverable unavailable states,
  exact-source inspection, and filtered pagination beyond the first 200 documents.
  Search returns supporting passages, not an automatically generated answer.
- First-run preparation initializes empty host baselines correctly, refreshes
  unresolved context lookups after preparation, and retains exact model identity
  and profile evidence through persistence. Finite model-residency restoration
  accounts for time spent reloading a model.
- Judge setup rejects stale connection checks and preserves explicit installed
  model choices. Comparison failures expose useful execution/context errors.
- Activity, routing, RAG, and evaluation surfaces distinguish missing, stale,
  and measured evidence. Prompt editing, source deletion, model menus, and
  Courthouse navigation have clearer feedback and keyboard behavior.
- External consumers and workers use bounded product APIs and versioned result
  contracts. Private adapters, operations, conversations, and secrets remain
  outside this repository.
- Tests use isolated Mongo fixtures, bounded workers, owned cleanup, and retained
  exit receipts. Several Windows HTTP suites use unique named pipes. Browser
  assets are served locally, and startup waits for published health endpoints.
- The product roadmap now describes practical feature and usability priorities
  and the CI that actually runs.

## Upgrade implications

This is a private-LAN prototype with **no built-in authentication**. Product
tokens, rate limits, public-exposure and same-origin operator guards, and trusted
UI proxy attestation were removed. `X-AgentX-Caller` is attribution only.
The default host ports bind to loopback and databases remain internal. Review
[Security](../../SECURITY.md) before reusing an older deployment configuration.

External extensions no longer receive a `security` object. The Pipeline
worker/operator authority split was removed. Old token and guard environment
variables no longer provide access control.

The former E2E gate suite, associated gate registries, and dedicated qualification
CI jobs were removed. Current CI runs each service's tests and renders Compose;
it does not replace checking the rendered installation. Existing generic
outbound target validation and runtime workload coordination remain in place.

Backups use a dedicated recovery volume. Database restore is disabled by
default, and an archive alone is not proof of a coherent restore. See
[Recovery](../RECOVERY.md) and [Install and update](../RELEASES.md). Keep existing
data and use an intentional upgrade; this release performs no automatic reset.

## Known limits

Intermittent local TCP/Mongo timeouts have occurred in a full native Windows
test run. Subsequent focused and full runs passed, but no root cause is proven.
Machine load and concurrent usage remain hypotheses to investigate on recurrence.
The named-pipe changes are not a claim that all Windows networking issues are fixed.

Quick comparison is a small workflow trial, not a comprehensive model ranking.
It requires matching measured contexts on the selected host. Full qualification,
large campaigns, and coherent restore/upgrade rehearsals remain separate work.
